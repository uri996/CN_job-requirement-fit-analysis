# 这是什么？

这是一个用于分析 **岗位要求与个人经历是否匹配** 的 Codex Skill。

可以简单理解成，一套已经整理好的分析规则和工作流程。安装以后，你不需要每次重新告诉 AI“应该怎么分析岗位”，它会按照这套规则自动处理。

你只需要提供：

- 想投递的岗位说明，也就是常说的 **JD（岗位描述）**
- 你的简历、项目经历、工作经历，或者其他相关背景

它会帮你判断：**这个岗位到底在招什么样的人，而你目前提供的经历和这些要求到底匹不匹配。**

当前支持三种求职场景：

- **实习**
- **校园招聘**
- **社会招聘**

这三种招聘方式不会使用完全相同的判断规则。例如：

- 实习岗位可能关心你是不是在校生、每周能实习几天；
- 校招岗位可能关心毕业届别、学历和专业要求；
- 社招岗位更关注近期工作经历、相关工作年限、实际负责过什么事情。

# 本 Skill 和普通的“简历匹配”有什么区别？

很多简单的岗位匹配工具，本质上是在做：

> JD 里有什么关键词
> ↓
> 简历里有没有这些关键词
> ↓
> 有得多 = 匹配
> 有得少 = 不匹配

这个 Skill 更关心：

```text
你实际做过什么
        ↓
这些经历证明了什么能力
        ↓
这些能力能不能对应岗位要求
```

而不是只看几个词有没有同时出现。

---

# 解决什么问题？

| 常见问题                                                   | 本 SKILL 的处理方式                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------ |
| 简历没写某项技能，就直接说“你不会”                         | 区分“没有证据”和“确认不会”，不会凭空判断能力缺失             |
| JD 写“相关专业优先”，却被当成硬性门槛                      | 区分“必须满足”“重要要求”“可以放宽”“优先考虑”                 |
| 实习、校招、社招全部用同一套判断方式                       | 三种招聘模式分别使用不同规则                                 |
| 岗位要求 5 年经验，候选人只有 3 年，于是其他能力全部被忽略 | 明确告诉你工作年限有风险，同时继续分析实际职责和能力是否匹配 |
| 转岗时只看上一份工作的职位名称                             | 看你实际做过什么，而不是只看职位名称                         |
| 很多年前用过某项技能，也被当成现在仍然熟练                 | 社招更加重视近期、持续、可以证明的职业经历                   |
| 用户没有提供某项信息，就直接判“不符合”                     | 标记为“信息不足”，其他可以分析的部分继续分析                 |
| 一个招聘页面里有多个岗位方向，分析时混在一起               | 拆成多个独立岗位分别判断，避免互相影响                       |
| 一个岗位的分析结果影响后面其他岗位                         | 每个岗位独立分析，完成后才能做比较                           |

# 支持哪些求职场景？

| 招聘方式     | 当前支持 | 主要关注内容                                                 |
| ------------ | :------: | ------------------------------------------------------------ |
| **实习**     |    ✅     | 在校身份、实习时间、岗位要求、已有项目和经历                 |
| **校园招聘** |    ✅     | 毕业届别、学历、专业、明确资格要求、项目和实习经历           |
| **社会招聘** |    ✅     | 近期工作经历、相关工作年限、实际职责、工作深度、经验是否过时 |

如果你没有告诉它自己是在找实习、校招还是社招，同时岗位说明里也看不出来，它会先问你。**不会自己瞎猜**。

# 它会告诉你什么？

一次完整的岗位匹配，通常会告诉你下面这些内容。

| 内容               | 说明                                               |
| ------------------ | -------------------------------------------------- |
| **当前招聘类型**   | 这个岗位应该按照实习、校招还是社招分析             |
| **资格和条件风险** | 例如学历、专业、毕业届别、工作年限是否存在明显问题 |
| **能力匹配情况**   | 你现有经历到底能不能证明岗位需要的能力             |
| **直接证据**       | 你哪些经历可以直接证明岗位需要的能力               |
| **可迁移经验**     | 虽然不是同一种工作，但哪些经历可以证明相关能力     |
| **简历证据缺口**   | 你可能会，但目前简历或材料里没有足够证据           |
| **信息缺口**       | 目前缺少哪些信息，所以暂时无法判断                 |
| **已确认差距**     | 现有材料已经可以明确确认的问题                     |
| **总体匹配结果**   | 对当前岗位给出整体判断                             |

总体匹配结果分为四种：

- **高匹配**
- **部分匹配**
- **低匹配**
- **信息不足**

它不会简单地数：

> “10 条要求，你中了 7 条，所以匹配度 70%。”

# 如何使用？

不需要记任何特殊命令。像平时聊天一样告诉 AI 你想做什么就可以。

---

## 案例 1：校招岗位匹配

```text
我准备按校招投这个岗位。

帮我看看这个岗位和我的经历是否匹配。

【岗位说明】

【我的简历或相关经历】
```

---

## 案例 2：社招岗位匹配

```text
我现在找社招。

帮我看看这个岗位和我的工作经历是否匹配。

【岗位说明】

【我的工作经历】
```

---

## 案例 3：只看岗位，不分析个人

```text
只帮我拆一下这个岗位说明。

不要结合我的个人经历，也不要判断我个人是否匹配。
```

这种情况下，它只会告诉你：

- 岗位主要做什么；
- 哪些要求比较重要；
- 哪些属于明确门槛；
- 哪些只是优先条件；
- 岗位整体想招什么样的人。

---

## 案例 4：工作年限不够，但还是想继续分析

```text
这个岗位要求 5 年相关工作经验，但我目前只有 3 年。

先告诉我这个年限差距有什么风险。

不要因为年限不够就停止，继续分析我的实际工作内容和岗位职责到底匹不匹配。
```

它会把**工作年限风险**和**实际能力匹配**分开告诉你。

---

## 案例 5：一个页面里有多个岗位方向

```text
这个招聘页面里有三个不同的岗位方向。

请把三个岗位拆开分别分析，不要把它们混成一个岗位。
```

---

## 案例 6：实习岗位的信息不完整

```text
我现在找实习。

这个岗位要求每周至少实习 4 天、连续 3 个月。

结合我已经提供的信息，告诉我目前哪些条件可以判断，哪些条件还需要我自己确认。
```

如果你没有告诉它自己每周到底能实习几天，它不会直接说：

> “你不符合。”

而是会告诉你：

> 这项条件目前缺少信息，需要你自己确认。

# 它是怎么判断的？

可以简单理解成下面这条流程：

```text
岗位说明 + 个人经历
        │
        ▼
判断招聘类型
        │
        ├── 实习
        ├── 校招
        └── 社招
        │
        ▼
检查明确资格和条件
        │
        ▼
分析你实际做过什么
        │
        ▼
判断这些经历证明了什么能力
        │
        ▼
把能力和岗位要求逐条对应
        │
        ▼
区分证据、风险和缺失信息
        │
        ▼
给出整体匹配结果
```

# 多个岗位为什么要分开分析？

假设一个招聘页面里同时写了：

```text
方向 A：产品运营

方向 B：技术运营

方向 C：开发者
```

如果把三个方向全部混在一起分析，很容易出现这种情况：

> A 岗位需要的能力，被错误地拿去评价 B 岗位。

所以 Skill 会先把它们拆成三个可以独立分析的岗位。然后：

```text
岗位 A → 单独分析
岗位 B → 单独分析
岗位 C → 单独分析
```

全部完成以后，才可以再进行**“哪一个更适合你？”**的比较。

# 设计原则

## 1. 没有证据，不等于不会

如果你没有在简历里写某项能力，**不代表 你一定不会**。所以 Skill 不会仅仅因为“没写”就直接确认能力缺失。

它会区分 **当前材料没有证据** 和 **现有信息已经证明你确实不满足**。

---

## 2. 资格风险和能力匹配分开

例如，岗位要求 5 年工作经验，而你只有 3 年。

**这个风险必须告诉你**。但是这不代表你的实际工作内容就不值得继续分析。

所以 **“资格和条件有没有风险”** 与 **“实际能力是否匹配”** 会分开处理。

---

## 3. 实习、校招和社招不能使用完全相同的规则

学生求职和有经验人士跳槽，不是一回事。

学生主要依靠：

- 实习；
- 课程项目；
- 个人项目；
- 比赛；
- 校园经历。

但一个已经工作 5 年的人再找社招，通常更应该看：

- 最近工作；
- 实际职责；
- 工作成果；
- 相关工作年限；
- 近期能力证据。

所以三种招聘模式必须分开处理。

---

## 4. 多个岗位独立分析

前一个岗位的结果不应该影响后一个岗位。因此，每个可以独立投递的岗位都会单独判断。全部分析结束以后，再进行岗位之间的比较。

# 当前不做什么

这个项目目前专注于：**判断岗位要求和候选人经历是否匹配。**它不是一个“什么都做”的全流程求职助手。

目前不负责：

- 自动搜索岗位；
- 自动投递；
- 自动研究公司背景；
- 完整代写简历；
- 批量生成求职信；
- 模拟面试；
- 提供面试题库；
- Offer 对比；
- 谈薪；
- 入职辅导。

这样做是为了保持边界清楚。把“岗位到底适不适合你”这件事做深，而不是每个求职环节都做一点。

# 常见问题

## Q：支持社招吗？

A：支持。当前正式支持 实习 / 校招 / 社招 三种招聘模式。

---

## Q：如果我的简历没写某项技能，会直接说我不会吗？

A：不会。Skill 会区分：

- 当前材料没有证据；
- 当前信息不足；
- 已经可以确认存在差距。

简单来说，**没写，不等于不会。**

---

## Q：可以一次分析多个岗位吗？

A：可以。如果一个招聘页面里有多个独立岗位方向，会先拆开分别分析。全部单独分析完成后，再进行比较。

---

## Q：这是关键词匹配吗？

A：不是。核心判断逻辑是：

```text
你做过什么
    ↓
证明了什么能力
    ↓
能不能对应岗位要求
```

关键词只能提供辅助信息。

---

## Q：社招是不是只看工作年限？

A：不是。还会看：

- 最近一份工作实际做了什么；
- 和目标岗位职责有多大重合；
- 工作经验是不是连续；
- 有没有独立负责过事情；
- 有没有跨团队推进经历；
- 某项能力是不是已经很多年没有使用；
- 现有证据是不是足够新、足够相关。

---

## Q：中间有几年没工作，会直接降低匹配结果吗？

A：不会因为“有空档期”本身自动扣分。真正需要判断的是：

> 你现在是否仍然有足够新的、相关的、可以证明的能力和经历。

至于面试时如何解释空档期，是另外一个问题，不属于本 Skill 当前负责的范围。

---

## Q：可以在其他 AI 软件里使用吗？

A：当前版本主要按照 **Codex 的技能机制**进行开发和验证。其中大部分招聘规则本身都是普通文本文件，因此理论上可以迁移到其他支持类似技能机制的 AI 工具。

但不同软件可能使用不同的：

- 技能安装方式；
- 文件目录；
- 调用方式；
- 上下文处理方式。

**所以目前不能保证，下载以后放到任何 AI 软件里都可以直接使用。**
